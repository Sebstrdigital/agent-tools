# Delegation

A clear task execution request is sufficient authority; no separate mode selection or Agreement confirmation. A proposal alone is not. Give the worker purpose, outcome, constraints/exclusions, acceptance, relevant rules/source and current candidate. A compact text packet is enough. No mandatory reading manifests or read receipts. File lists are pointers unless the user explicitly restricted them; necessary supporting files remain within the requested outcome.

Include the owning project root, project-local task workspace/worktree paths, retained-output locations, approved external exceptions and cleanup responsibility in the packet and continuations. Follow [project-local artifacts and housekeeping](../../../docs/workflows/project-artifacts.md). Workers reconcile their disposable files/resources under applicable cleanup authority before handoff; return useful evidence, retained purposes and blockers. The lead verifies housekeeping rather than assuming worker completion implies cleanup.

Choose the roles needed for the task, not a compulsory three-role cycle per slice. Fixed builder, no-edit validator, inspection-only reviewer and read-only Scout grants remain available. Carry the agreed task boundary to each role: the broader sprint or product plan is context, not permission to add its other tasks. Ask workers to distinguish task blockers, release risks and separable follow-ups; the lead assesses findings against acceptance and safety rather than automatically turning suggestions into requirements. Surface serious risks honestly. Preserve requested independent gates; the lead alone inspects and accepts.

Use the installed tmux controls with a persistent parent session. Models follow configured routing; saved grants/model/context policies remain pinned. Authority references describe the user's existing request, not another approval to obtain. Developer takes compact text or its legacy structured packet; selection is optional compatibility metadata. See ../../../docs/lean-workflows.md.

Independent tasks can run concurrently in distinct linked worktrees via subagent/developer cwd. Same-workspace ownership is exclusive, including pause/wait, except for pinned reviewers on the same verified clean Git candidate; see [parallel guidance](../../addy-engineering/references/parallel-work.md) for limitations. Use current checkout or an existing linked worktree, not an arbitrary path. No nested workers. Do not blindly merge, reset or clean another person's work.

Results/questions arrive automatically; do not poll. Use exact owned names and matching runId/questionId for answers. Pause preserves the pane; rearm supplies new in-scope work. Resume carries original authority references without asking the user again. Changed permission/outcome needs a real decision.

Once delegation is selected, the lead coordinates/scopes work; reads returned evidence; inspects source diffs, logs, screenshots and release metadata; maintains coordination notes; and alone accepts. Workers—not the lead—execute product/supporting-file edits, diagnosis/repair, tests/build/browser/API validation and environment lifecycle under their role grants. Commit, push, merge-request creation, merge, deploy and publication are worker execution actions only under applicable authority. Lead shell/API use is read-only evidence inspection; executing validation belongs to a worker. No quick-fix or one-line exception applies. Direct remains valid for small tasks, but delegated work may switch to Direct only explicitly after worker ownership/resources are reconciled. A red check or worker struggle is not a silent-takeover exception: continue, redirect or replace after reconciliation, never as a red-check workaround. Ordinary compiler/test/harness corrections and actionable review findings authorize diagnosis and repair within the task. Do not invent repair caps or minute pools. Optional assignment binds user-requested cumulative execution limits; repairAttempts is optional, never mandatory bookkeeping or a quota for each compiler error. Existing declared limits remain binding. A terminal same-role replacement uses original authority, partial-source identities, findings, reconciled resources and remaining declared allowance. One replacement is supported, as with TAKT's stronger worker retry; useful same-worker repairs are not replacement attempts.

New workers load project context/skills/templates/themes; executable extension/MCP discovery remains denied without a trust mechanism. This is not an OS sandbox. Legacy saved snapshots retain all original denials; do not widen them on resume.

Return concise changed paths/candidate, actual checks/exits, gaps, decisions and evidence pointers. Keep raw logs on disk. Reuse unchanged evidence; renew affected checks/review and final integrated evidence proportionately. Stop for actual new authority, explicit exhausted limits or demonstrated no progress, not another red check. New private-data access, live application control and destructive/outward actions need applicable permission. Finish with the candidate, consolidated manual checks and honest gaps.
